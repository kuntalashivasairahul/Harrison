HarrisonGPT — Clinical Print

A visual system for a medical reference that renders beside scans of printed pages. Every colour pair below is contrast-verified. Self-contained: no fonts, no CDN, no JS dependencies.

The ground is warm because scanned book paper is roughly #F4F1EA. On pure white every page scan reads as grey and dirty. ink-300 started life at #A69C91 and measured 2.54:1 — it would have failed AA on the page labels that carry provenance. Darkened until it passed.

Answer prose is serif at 17px/28px, capped at 68ch — it is textbook prose set beside a scanned textbook page, and it is read rather than skimmed. Chrome is sans. Page labels and timings are mono with tabular figures so numbers don't jitter as they update.

03 · Confidence & refusal — the load-bearing states

●●●High confidence ●●○Medium confidence ●○○Low confidence
Refusal — rendered verbatim

Insufficient information in the provided context.

Low is slate, not red. Red would collide with the oxblood accent and over-signals — low confidence is uncertainty, not an error. Never colour alone: every state carries a glyph and the literal word, because a colourblind resident reading a dosage must not be one hue away from misreading the system's own hedge. Refusal is its own state — no warning triangle, no emoji, no "try rephrasing", no softening of any kind.

Every [p:NNN] becomes a focusable chip; activating it highlights that page in the rail, and the rail opens the full PNG in a lightbox. Scans are square-cornered — a book page is a rectangle, and rounding it is a small lie about the artefact. Below 900px the rail collapses and citations open a sheet instead.

05 · Pipeline strip & the 40-second wait

retrieval 0.41srerank 0.22s draft 6.14sverify 3.30stotal 10.31s
optimizer 0.7sretrieval 0.4s rerank 0.2sdrafting…verify

/ask blocks for 10–40s with no token stream, so a spinner reads as a hang. The skeleton is labelled with the pipeline's real stage names. Known ceiling: timings only arrives with the answer, so mid-flight progress is an estimate — on a slow request it sits at "drafting" longer than it claims. The honest fix is an SSE endpoint; that is a backend change and shouldn't gate the UI. This is the only looping animation in the system.

06 · Controls

The mode toggle is one request field (mode), but it produces visibly different artefacts — structured synthesis with a Quick Revision block, versus dense prose. Worth a segmented control, not a dropdown. Focus rings are 2px accent at 2px offset, never removed.

Exactly one shadow exists in this system — the lightbox overlay. Everything else is a 1px ink-100 border. Paper does not float. This single rule prevents most of the drift that makes an interface look generic.

A medical reference that looks like a landing page for a Series A undermines its own credibility before a word is read. Dark mode is deliberately absent in v1: every scan is white paper and would glow in a dark shell. All values route through tokens, so it is later one [data-theme] block — not a refactor.
